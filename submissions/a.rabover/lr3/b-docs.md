# (б) Руководство интегратора - ММСБ

Учебный контракт 1.0.0. Все примеры условные. Доступ по HTTPS через внешний шлюз, без BFF и закрытого корпоративного контура. Адреса тестового и продуктивного шлюзов, наличие тестового доступа, сетевые ACL и порядок выдачи секретов уточняются при подключении `[?]`. Тесты в продуктивном контуре запрещены.

## Подключение

По проекту администратор создаёт субаккаунт интеграции с правами и лимитом. Программа получает реквизиты приложения по защищённому каналу и токен через Client Credentials Flow (адрес и формат реквизитов `[?]`). В запросах используется `Authorization: Bearer <access_token>`, подпись тела не нужна. Истёкший токен заменяется новым. Секреты не хранятся в репозитории и журналах. Клиент определяется сервером, права проверяются при каждом запросе.

В действующей системе известна пара «токен приложения + ключ пользователя» (З-12). Отдельная учётная запись программы - учебное решение. Факт курса: квота шлюза 1000 запросов в сутки, код 509. В проекте - 1000 запросов в сутки на клиента, 429 и Retry-After. Таймаут клиента 30 с, смежного вызова 10 с. Лимит всплесков неизвестен.

## Оформление одного возврата

`POST /1.0/returns`: обязательны originalBarcode (14 цифр, доступное отправление) и returnReason (BUYER_REFUSAL или OTHER; при OTHER обязателен returnReasonComment). Тариф, адрес и реквизиты берутся из отправления и договора (учебное допущение), при нехватке данных - 400. Стоимость удерживается в пределах лимита. 201 SUBMITTED подтверждает оформление и запись в return_outbox; ШПИ появится в REGISTERED. Постоянный отказ или дедлайн 24 ч после сверки -> REJECTED и освобождение удержания. Вручённое исходное отправление или истёкший срок -> 409. Ключ идемпотентности обязателен.

```http
POST /1.0/returns HTTP/1.1
Host: api.example.invalid
Authorization: Bearer <access_token>
Content-Type: application/json
Idempotency-Key: 9b1d6e2a-0c4f-4a8e-b7d3-5e6f7a8b9c0d

{"originalBarcode":"12345678901234","returnReason":"BUYER_REFUSAL"}
```

```http
HTTP/1.1 201 Created
Content-Type: application/json

{"returnId":"3f2b8c1e-7a4d-4e5b-9c0a-12ab34cd56ef","originalBarcode":"12345678901234","state":"SUBMITTED","createdAt":"2026-11-25T10:00:00Z","barcode":null,"returnReason":"BUYER_REFUSAL","stateUpdatedAt":"2026-11-25T10:00:00Z","financialState":"HELD"}
```

## Отмена

`POST /1.0/returns/{returnId}/cancel`: разрешена для DRAFT, SUBMITTED до начала регистрации и REGISTERED до приёма. При выполняющейся или неопределённой регистрации - 409 REGISTRATION_IN_PROGRESS. Для REGISTERED снимается регистрация, затем удержание (если есть). `reason`: CLIENT_REQUEST, DUPLICATE, WRONG_DATA, OTHER; `comment` до 500 символов, при OTHER обязателен. Ключ рекомендован. Повтор отмены возвращает исходный результат без двойного освобождения средств.

```http
POST /1.0/returns/3f2b8c1e-7a4d-4e5b-9c0a-12ab34cd56ef/cancel HTTP/1.1
Host: api.example.invalid
Authorization: Bearer <access_token>
Content-Type: application/json
Idempotency-Key: 04d968ab-e0c5-49ea-bd39-11f408fa0e11

{"reason":"WRONG_DATA","comment":"Указан неверный адрес"}
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"returnId":"3f2b8c1e-7a4d-4e5b-9c0a-12ab34cd56ef","state":"CANCELLED","previousState":"SUBMITTED","cancelledAt":"2026-11-25T10:01:00Z","barcode":null,"reason":"WRONG_DATA"}
```

## Перечень

`GET /1.0/returns`: доступные интеграции возвраты. Необязательные параметры: state, limit (1-100, по умолчанию 50), cursor. Сортировка createdAt и returnId по убыванию. Передавайте nextCursor с прежними фильтром и limit; null - конец. Курсор привязан к субъекту и фильтрам, неверный - 400. Снимок не гарантируется, исключайте дубли по returnId. Пустая выборка - 200 с пустым items.

```http
GET /1.0/returns?state=CANCELLED&limit=50 HTTP/1.1
Host: api.example.invalid
Authorization: Bearer <access_token>
```

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"items":[{"returnId":"3f2b8c1e-7a4d-4e5b-9c0a-12ab34cd56ef","originalBarcode":"12345678901234","state":"CANCELLED","createdAt":"2026-11-25T10:00:00Z","barcode":null,"returnReason":"BUYER_REFUSAL","stateUpdatedAt":"2026-11-25T10:01:00Z","financialState":"RELEASED"}],"nextCursor":null}
```

Состояния и financialState перечислены в OpenAPI. stateUpdatedAt - время последнего изменения или подтверждения статуса. Перечень показывает последние известные данные без синхронного запроса в трекинг. При приёме возможна корректировка по весу; повтор события не списывает деньги повторно. Опрос для ММСБ - не чаще раза в минуту с учётом квоты (учебная рекомендация).

## Ошибки и повторы

Код HTTP определяет класс действия, code - стабильную причину, message - изменяемое пояснение, traceId - идентификатор для поддержки. currentState обязателен при 409 отмены и может уточнять другие конфликты, details - ошибки полей.

```http
HTTP/1.1 503 Service Unavailable
Retry-After: 30
Content-Type: application/json

{"code":"CIRCUIT_OPEN","message":"Оформление временно недоступно; вызов сервиса не выполнен","traceId":"example-trace"}
```

| HTTP / code | Что делать |
|---|---|
| 400 VALIDATION_ERROR, INVALID_BARCODE | Исправить данные; новая команда с новым ключом. |
| 401 UNAUTHORIZED | Получить токен и повторить исходную команду. |
| 403 FORBIDDEN | Обратиться к администратору; не повторять до изменения прав. |
| 404 RETURN_NOT_FOUND, SHIPMENT_NOT_FOUND | Проверить ID и доступную область; не повторять автоматически. |
| 409 RETURN_ALREADY_IN_TRANSIT, RETURN_CLOSED | Отмена невозможна; не повторять. |
| 409 REGISTRATION_IN_PROGRESS | Дождаться завершения регистрации, проверить перечень, затем при допустимом состоянии повторить отмену. |
| 409 SHIPMENT_ALREADY_DELIVERED, RETURN_WINDOW_EXPIRED | Исходное отправление вручено или срок возврата истёк; повтор бессмыслен. |
| 409 RETURN_ALREADY_EXISTS | Найти существующий возврат через перечень; не создавать дубль. |
| 409 INSUFFICIENT_FUNDS, LIMIT_EXCEEDED | Проверить баланс/лимит, после исправления - новая команда. |
| 422 IDEMPOTENCY_KEY_MISMATCH | Восстановить исходное тело или сформировать новый ключ для новой команды. |
| 429 RATE_LIMIT_EXCEEDED | Ждать Retry-After, повтор с тем же ключом. |
| 500 INTERNAL_ERROR | Временная ошибка; повтор с тем же ключом. |
| 502 UPSTREAM_UNAVAILABLE | Реальный вызов зависимого сервиса завершился отказом; повтор с тем же ключом. |
| 503 CIRCUIT_OPEN | Сервис не вызывался, ждать Retry-After. |
| 503 SHIPMENT_API_UNAVAILABLE, DEPENDENCY_UNAVAILABLE | Не подтверждён эффект зависимости; ждать Retry-After, повторить с тем же ключом. |
| 504 UPSTREAM_TIMEOUT | Вызов был, ответ не получен; повторить с тем же ключом. |

При временной ошибке или отсутствии ответа повторяйте POST с исходным ключом, GET - с прежними параметрами. Соблюдайте Retry-After; без него паузы 2, 4, 8 с со случайным разбросом (учебные значения). После трёх повторов сверяйте перечень и обращайтесь в поддержку с traceId. При неизвестном исходе новую команду не создавайте.

Idempotency-Key - UUID на логическую команду, до 64 символов. Результат хранится 24 ч (учебное значение) в области клиента, субъекта и операции; сравниваются путь и нормализованное тело. Параллельный повтор ждёт исходную команду или получает временную ошибку. Незавершённые записи сохраняются до сверки, финансовые ключи долговечны. После 24 ч нужна сверка. Права проверяются при повторе.

Совместимость: игнорируйте неизвестные поля ответа. Изменение обязательных полей, смысла, пути или значений состояний требует новой версии /2.0 с сохранением старой. Числа проекта - учебные допущения.
