## Сквозной пример

Клиент подаёт заявку. После проверки условий и удержания стоимости оформляется встречное отправление с собственным ШПИ. Когда отделение принимает его, возникает основание для окончательного списания. Если приём не состоялся и это подтверждено, удержание освобождается. В кабинете отдельно видны состояние заявки, последнее известное состояние посылки и статус расчёта. Отчёт строится по подтверждённым событиям и показывает, до какого момента обработаны данные ЛК.

Движение денег описано по учебному условию З-7; действующие правила расчётов для возвратных отправлений в материалах не установлены. Ссылки на занятия указывают на источник исходных сведений. Состояния, новые поля, контракты и эксплуатационные параметры ниже предлагаются в рамках проекта.

## Что изменилось относительно черновиков

Отдельные бланки практикумов не заполнялись. При сборке проверены стыки требований З-5–З-9; ниже приведены изменения первоначальной модели этой работы.

| Что не сходилось | Как согласовано |
|---|---|
| Один статус «возврат завершён» объединял заявку, доставку и деньги: по нему нельзя понять, почему посылка уже едет, а списание ещё не подтверждено. | Разделены состояние заявки в ЛК, статус встречного отправления в почтовой сети и состояние финансовой операции. Привязка списания — к подтверждённому приёму; логистика при сбое биллинга продолжает обновляться. |
| Результат массового задания трактовался как доставка возврата. Тогда задание могло оставаться «в работе» до вручения посылки. | Успешная строка означает оформленное встречное отправление. После этого доставку и деньги смотрят по заявке. Для неоднозначной операции строка получает исход «требует вмешательства» с сохранением ссылки на заявку. |
| Отчёт по причинам предполагал, что у каждого возврата будет известна причина сразу при оформлении. В проекте источник мог уточнить её позднее. | Введено отдельное событие обновления трекинга с исходным кодом причины; в отчёте выделено «неизвестно». Повтор сообщения не увеличивает счётчик. |
| Истечение срока ожидания ответа смежной системы воспринималось как отказ. Это могло привести к повторному удержанию или освобождению денег при уже принятом отправлении. | Неопределённый результат ведёт на проверку по прежнему ключу операции. Освобождение средств разрешено только после подтверждения, что приёма не было и он больше невозможен. |
