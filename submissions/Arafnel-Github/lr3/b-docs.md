# Документация разработчика: API Управления возвратами (v1)

Данное руководство содержит сведения, достаточные для подключения внешней учётной системы (ERP/WMS) к интерфейсу управления возвратами без обращения в службу поддержки

## 1. Аутентификация и получение доступа

### 1.1. Выпуск учётных данных (техническая учётная запись)
Для программной интеграции запрещено использовать логин и пароль живого сотрудника (смена пароля человеком остановит обмен, а все финансовые списания запишутся в аудит на физическое лицо)
1. Администратор вашей компании в личном кабинете создаёт субаккаунт с ролью "Интеграция (API)" и задаёт ему суточный денежный лимит удержаний
2. В разделе настроек интеграции формируется пара секретов: `client_id` (идентификатор приложения) и `client_secret` (секретный ключ)

### 1.2. Получение и передача токена
Авторизация работает по протоколу OAuth 2.0 (Client Credentials Flow):
1. Выполните POST-запрос на внешний эндпоинт сервиса идентификации (`https://auth.postal-cabinet.example/oauth2/token`) с передачей `client_id` и `client_secret`
2. В ответ вы получите JWT-токен доступа (`access_token`) со временем жизни 3600 секунд (1 час, учебное допущение). Токен обновления (`refresh_token`) не выдаётся - при истечении срока программа запрашивает новый токен по своим реквизитам
3. Каждый запрос к API возвратов должен содержать заголовок:
   ```http
   Authorization: Bearer <ваш_access_token>
   ```
   
## 2. Сетевые и эксплуатационные условия доступа

Перед началом разработки убедитесь, что ваша инфраструктура соответствует правилам периметра:
- Публичный API доступен из сети Интернет через внешний шлюз (https://api.postal-cabinet.example/v1) по протоколу HTTPS (TLS 1.2 и выше). Внутренний контур организации закрыт
- На внешнем шлюзе действует суточная квота - 1 000 запросов в сутки на аккаунт (данные системы). При превышении шлюз отклоняет вызовы до начала следующих суток
- Не более 10 запросов в секунду (RPS) на один токен интеграции (учебное допущение)
- Устанавливайте таймаут ожидания ответа на стороне вашего HTTP-клиента не менее 10 секунд (так как внутренний таймаут обращения кабинета к смежным службам составляет 5 секунд - учебное допущение)
- Все изменяющие запросы (POST) требуют обязательного заголовка Idempotency-Key в формате UUID v4. Ключ хранится 15 суток. Повторный запрос с тем же ключом и идентичным телом вернёт результат первой операции без повторного удержания денег

## 3. Пример выполнения операции: Оформление возврата

Запрос
```http
    POST /v1/returns HTTP/1.1
    Host: api.postal-cabinet.example
    Authorization: Bearer eyJhbGciOiJSUzI1NiIsInR5cCI6IkpXVCJ9...
    Idempotency-Key: 9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb6d
    Content-Type: application/json
    
    {
      "original_barcode": "12345678901234",
      "return_reason_code": "UNCLAIMED",
      "comment": "Заказ №4581 не выкуплен в срок"
    }
```

Успешный ответ (201 Created)

```http
    HTTP/1.1 201 Created
    Content-Type: application/json
    
    {
      "return_id": "ret_99321",
      "original_barcode": "12345678901234",
      "status": "CREATED",
      "hold_amount_rub": 320.50,
      "created_at": "2026-11-25T14:30:00Z"
    }
```
(Примечание: если сумма удержания превышает лимит автоодобрения, вернётся код 202 Accepted со статусом PENDING_APPROVAL - возврат попадёт в очередь на подтверждение вашему старшему бухгалтеру)


## 4. Обработка ошибок и политика повторов

Все ошибки возвращаются в едином JSON-формате {"code": "...", "message": "..."}. Поле code является частью контракта; текст в message предназначен только для чтения человеком и может меняться


| HTTP-код | Машиночитаемый `code`                     | Причина возникновения                                                                        | Действия вашего приложения                                                                                                                                      |
|:---------|:------------------------------------------|:---------------------------------------------------------------------------------------------|:----------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 400      | `INVALID_BARCODE` / `VALIDATION_ERROR`    | Неверный формат ШПИ (нужно 14 цифр) или обязательного поля                                   | Не повторять. Исправить данные на стороне вашей системы                                                                                                         |
| 400      | `IDEMPOTENCY_KEY_BODY_MISMATCH`           | Ключ `Idempotency-Key` уже использовался ранее, но тело запроса изменилось                   | Не повторять. Сгенерировать новый UUID для нового запроса                                                                                                       |
| 401      | `TOKEN_EXPIRED` / `INVALID_TOKEN`         | Срок жизни JWT-токена истёк                                                                  | Запросить новый `access_token` у сервиса идентификации и повторить запрос                                                                                       |
| 403      | `SUBACCOUNT_LIMIT_EXCEEDED`               | Превышен суточный денежный лимит удержаний, заданный для роли "Интеграция"                   | Не повторять. Уведомить администратора вашей компании для увеличения лимита                                                                                     |
| 403      | `FORBIDDEN_OPERATION`                     | Попытка отменить возврат, который был оформлен вручную сотрудником через экран               | Не повторять. Отмена разрешена только для возвратов, созданных этим же API-ключом                                                                               |
| 404      | `RETURN_NOT_FOUND` / `SHIPMENT_NOT_FOUND` | Отправление или возврат не найдены либо принадлежат другому юридическому лицу                | Не повторять. Проверить корректность переданного идентификатора                                                                                                 |
| 409      | `INVALID_STATE_TRANSITION`                | Невозможно отменить возврат: посылка уже принята в отделении (`ACCEPTED_AT_OFFICE`)          | Не повторять. Обновить статус возврата в своей системе через `GET /v1/returns`                                                                                  |
| 422      | `INSUFFICIENT_FUNDS`                      | На общем балансе компании недостаточно средств для удержания пересылки                       | Пополнить баланс компании, после чего повторить запрос с новым ключом идемпотентности                                                                           |
| 429      | `RATE_LIMIT_EXCEEDED`                     | Превышена интенсивность вызовов (RPS)                                                        | Повторить строго через количество секунд, указанное в заголовке `Retry-After`                                                                                   |
| 500      | `INTERNAL_SERVER_ERROR`                   | Непредвиденный внутренний сбой на нашей стороне                                              | Повторить с тем же `Idempotency-Key`, используя экспоненциальную паузу (например, 2 с, 4 с, 8 с)                                                                |
| 503      | `CIRCUIT_BREAKER_OPEN`                    | Временная изоляция отказа: смежный сервис (баланс/отправления) деградировал, цепь разомкнута | Не отправлять запросы до истечения паузы. Считать заголовок `Retry-After` (например, `10` с) и повторить ровно через указанное время с тем же `Idempotency-Key` |
