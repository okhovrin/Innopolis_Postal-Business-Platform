# Ролевая модель

Клиент - организация с договором. Пользователь - отдельный субъект, действующий от её имени. У одного клиента много пользователей, а один человек может быть связан с несколькими клиентами. client_id организации не равен subject_id пользователя или идентификатору приложения.

## Роли

| Роль | Уровень | Назначение |
|---|---|---|
| Администратор | Администратор аккаунта | Оформляет, читает и отменяет возвраты своего клиента |
| Оператор | Субаккаунт | Оформляет в пределах лимита, читает и отменяет свои возвраты |
| Бухгалтер | Субаккаунт | Читает результаты клиента для сверки, не оформляет и не отменяет |
| Аудитор | Субаккаунт | Читает результаты клиента для проверки, ничего не меняет |

## Матрица прав

Три измерения - субъект с ролью, операция и множество объектов. "Свои" у оператора означает created_by = subject_id, не все объекты организации. Во всех разрешённых клетках дополнительно требуется активная связь субъекта с client_id.

| Операция | Администратор | Оператор | Бухгалтер | Аудитор |
|---|---|---|---|---|
| createReturnJob | Отправления своего клиента; задание создаётся в своём клиенте | Отправления своего клиента в пределах личного лимита; задание записывается на оператора | Запрещено | Запрещено |
| getReturnJob | Все задания своего клиента и их строки | Только задания своего клиента, созданные этим субъектом, и их строки | Все задания своего клиента и их строки | Все задания своего клиента и их строки |
| cancelReturn | Возвраты своего клиента в NEW/READY; повтор для CANCELLING/CANCELLED | Только созданные этим субъектом возвраты своего клиента в NEW/READY; повтор для CANCELLING/CANCELLED | Запрещено | Запрещено |
| Вход через API | Только приложение, привязанное к этому клиенту и роли, при api_enabled | То же для роли оператора | То же для роли бухгалтера, только чтение | То же для роли аудитора, только чтение |

Scope ограничивает операции, но не заменяет роль и область видимости. На входе через API требуется и api_enabled, и scope нужного метода, и разрешённая клетка. Отключение api_enabled закрывает программный вход, даже если токен ещё не истёк.

Отдельные методы выгрузки, списка всех возвратов и управления ролями в эти три операции не входят. Просмотр перечня строк и текущих состояний выполняется getReturnJob.

## Проверки на сервере

1. Проверить токен и отзыв, определить subject_id. Получить выбранный client_id из доверенной связи, проверить её актуальность.
2. Проверить api_enabled, scope и текущую роль. При недоступности источника прав - 503 AUTHORIZATION_UNAVAILABLE, доступ не разрешается по старой роли из токена.
3. Встроить область видимости в запрос к данным. Для getReturnJob оператора: читаем job_id среди заданий `client_id = context.client_id AND created_by = context.subject_id`. Для остальных читающих ролей - среди `client_id = context.client_id`. Чужой и отсутствующий объект дают одинаковый 404.
4. При createReturnJob воркер ищет shipment_id среди отправлений context.client_id. При cancelReturn ищется return_id с фильтром клиента и, для оператора, автора. Эти же проверки действуют для повтора по ключу идемпотентности.
5. Перед новым HOLD воркер повторно проверяет актуальное право, доступный лимит субаккаунта и остаток у авторитетного источника. Удержание и расход лимита фиксируются атомарно, иначе параллельные строки могут превысить лимит.

Право, отозванное до HOLD, не позволяет создать новое удержание: строка получает ACCESS_DENIED. Уже выполненное HOLD нельзя просто бросить при отзыве права.

Администратор не может расширить свою область за пределы клиента и снять лимит, установленный договором. Изменения ролей идут отдельным контролируемым процессом с аудитом.

## Выбор модели

Используется сочетание ролей и атрибутов. Роли отвечают за разрешённые операции, атрибуты - за client_id, created_by, api_enabled, лимит и состояние заявки. Одних ролей мало: роль "оператор" есть у разных клиентов.

## Проверка на обход

| Попытка | Почему она запрещена |
|---|---|
| Оператор подставляет job_id другого клиента | Фильтр client_id даёт 404 до чтения строк |
| Оператор подставляет задание коллеги своего клиента | Дополнительный фильтр created_by даёт 404 |
| Аудитор вызывает отмену через API вместо экрана | Та же матрица запрещает cancelReturn; API не обход прав |
| Программа использует старый токен после отзыва права оформления | Проверяются текущие права на входе и перед новым HOLD |

## Аудит

Для оформления и отмены сохраняются subject_id, client_id, идентификатор приложения для API, операция, job_id/return_id, время UTC, результат и причина отказа. Для HOLD и RELEASE добавляются ключ денежной операции и подтверждённый результат без секретов.
