# Запуск размыкателя

Нужен Python 3.10 или новее, внешних пакетов нет. Из папки circuit_breaker:

```bash
python demo.py
```

Если Windows показывает русский текст неверно, перед запуском в PowerShell нужно выполнить `$env:PYTHONIOENCODING='utf-8'`.

## На какой связи стоит

REST API -> API отправлений, вызов create_return. Это связь регистрации из карты в README и ЛР-2. Пока сервис недоступен, воркер сохраняет задачу и откладывает передачу. Открытая цепь не отменяет удержание и не доказывает, что предыдущий запрос не был принят.

FakeReturnsService заменяет внешний сервис, FakeClock позволяет пройти паузы без ожидания. Экземпляр рассчитан на задачи одного asyncio event loop, один пробный вызов допускается одновременно. Для разных процессов координация проб здесь не реализуется.

## Параметры

Все значения - учебные допущения для демонстрации.

| Параметр | Значение | Почему |
|---|---|---|
| Скользящее окно | 60 секунд | Учитываем недавнее состояние зависимости |
| Порог отказов | 0.5 | Размыкаем, если отказы составляют хотя бы половину |
| Минимум вызовов | 4 | Не принимаем решение по одному случайному отказу |
| Начальная пауза OPEN | 10 секунд | Даём сервису передышку |
| Предел растущей паузы | 40 секунд | Паузы после провала проб: 20, 40, затем 40 |
| Таймаут вызова | 2 секунды | Ограничивает ожидание даже в HALF_OPEN |
| Предел HALF_OPEN | 5 секунд | Ошибки запроса не оставляют цепь в пробном режиме бессрочно |

Пауза 10 секунд больше таймаута 2 секунды в 5 раз. Предел HALF_OPEN 5 секунд больше таймаута 2 секунды: одна проба успевает завершиться или получить таймаут. Порог медленного вызова отдельно не вводится, зависший вызов становится ServiceTimeout. Это проще, чем считать одновременно ошибки и медленные ответы.

Окно считается по времени завершения вызовов. До minimum_calls цепь не размыкается. InvalidRequest и BusinessRejected не входят ни в числитель, ни в знаменатель. При HALF_OPEN такая ошибка не доказывает восстановление: пробный слот освобождается, но состояние остаётся до корректной пробы или предельного времени. Успешная проба очищает окно и сбрасывает паузу.

Переход OPEN -> HALF_OPEN происходит при следующем вызове после паузы. Истечение предела HALF_OPEN проверяется при обращении к состоянию или новом вызове, а активная проба ограничена asyncio.wait_for. Операция должна быть асинхронной, без блокирующего ввода-вывода и без подавления отмены. Отмена ожидания не отменяет уже сделанное действие во внешней системе: перед повтором нужны прежний ключ и сверка.

## Вывод демонстрации

```text
1. Последовательные отказы
Отказ 1: 503 DEPENDENCY_UNAVAILABLE, Retry-After=-
  Цепь: CLOSED; вызовов сервиса за попытку: 1
Отказ 2: 503 DEPENDENCY_UNAVAILABLE, Retry-After=-
  Цепь: CLOSED; вызовов сервиса за попытку: 1
Отказ 3: 503 DEPENDENCY_UNAVAILABLE, Retry-After=-
  Цепь: CLOSED; вызовов сервиса за попытку: 1
Отказ 4: 503 DEPENDENCY_UNAVAILABLE, Retry-After=-
  Цепь: OPEN; вызовов сервиса за попытку: 1
Запрос при OPEN: 503 CIRCUIT_OPEN, Retry-After=10
  Цепь: OPEN; вызовов сервиса за попытку: 0
2. Неудачный пробный запрос
  Пробный вызов: HALF_OPEN
Неудачная проба: 503 DEPENDENCY_UNAVAILABLE, Retry-After=-
  Цепь: OPEN; вызовов сервиса за попытку: 1
Запрос после неудачной пробы: 503 CIRCUIT_OPEN, Retry-After=20
  Цепь: OPEN; вызовов сервиса за попытку: 0
3. Восстановление сервиса
  Пробный вызов: HALF_OPEN
Успешная проба: 200, return_id=r501
  Цепь: CLOSED; вызовов сервиса за попытку: 1
Обычный запрос после восстановления: 200, return_id=r501
  Цепь: CLOSED; вызовов сервиса за попытку: 1
```

При OPEN внешний вызов не сделан. После паузы пропускается одна проба, неудачная снова размыкает цепь и увеличивает паузу, успешная возвращает CLOSED.

## Что получает клиент

| Ситуация | HTTP-представление ошибки адаптера | Отличие |
|---|---|---|
| OPEN или занятый пробный слот | 503 CIRCUIT_OPEN, Retry-After и retry_after_seconds | Сетевого вызова не было |
| Сервис отказал | 503 DEPENDENCY_UNAVAILABLE | Вызов был сделан |
| Вызов превысил таймаут | 503 DEPENDENCY_TIMEOUT | Вызов был сделан, результат может остаться неизвестным |
| Неверные данные | 400 INVALID_REQUEST | Исправить запрос, счётчик отказов не меняется |
| Окончательный бизнес-отказ | 422 RETURN_NOT_ALLOWED | Повтор не поможет, счётчик не меняется |

У всех ошибок code, message и details. Для обычного отказа адаптер не знает время восстановления; повтор назначает воркер по правилам ЛР-2.

В публичном API createReturnJob возвращает 202 до работы с этой зависимостью. Воркер сохраняет CIRCUIT_OPEN или DEPENDENCY_UNAVAILABLE в pending_error строки, а клиент получает их через getReturnJob при HTTP 200. После окончательного бизнес-отказа воркер компенсирует удержание, и строка получает REJECTED с RETURN_NOT_ALLOWED. После истечения deadline_at при неизвестном результате - MANUAL и INTERVENTION. Открытая цепь не меняет входной запрос в 400 и не создаёт новое задание.

## Проверка

```bash
python test_breaker.py
```

Проверяются три сценария задания, отсутствие вызова при OPEN, минимум и доля отказов, очистка временного окна, игнорирование ошибок запроса, одна одновременная проба, предел HALF_OPEN, реальный таймаут и предел растущей паузы.
