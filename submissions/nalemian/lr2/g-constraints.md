# Ограничения унаследованного ландшафта

Основа - конкретные границы схемы З-5: отдельные REST API, Онлайн Баланс, сервис отслеживания, доступ к почтовым операциям через REST-обвязку корпоративной шины и внешние финансовые системы. Наличие функций ниже нужно проверить по контрактам; отсутствие этих функций рассматривается как условие, при котором целевое решение недостижимо.

| Конкретное ограничение | Что становится недостижимым | Обход и его цена                                                                                                                                                                                                                                                      |
|---|---|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Почтовые операции доступны только через REST-обвязку корпоративной шины, без прямого потока событий | Нельзя строить DEBIT в расчёте на мгновенный push о физическом приёме | Сервис отслеживания опрашивает операции с сохранённой позицией, перекрытием окна и дедупликацией; задержка отображается пользователю. Если обвязка вообще не отдаёт приём, требуется доработка интеграции или ручное подтверждение                                    |
| API отправлений не поддерживает устойчивый ключ и поиск результата по нему | После потерянного ответа невозможно безопасно повторить регистрацию и гарантировать отсутствие второго отправления | Сохранить намерение и корреляцию в адаптере; сначала сверять по внешнему идентификатору. Если внешний результат невозможно найти, MANUAL вместо слепого повтора. Один локальный адаптер не делает неидемпотентный внешний API идемпотентным                           |
| Онлайн Баланс или финансовый контур не поддерживает атомарную уникальность бизнес-ключа и проверку операции | Невозможно гарантировать однократное списание при повторном сообщении о приёме | Учёт операций и проверка ключа в авторитетном денежном контуре; согласование такого контракта. Если изменить контур нельзя, последовательное исполнение со сверкой и ручной обработкой неопределённого результата; гарантия автоматического восстановления ограничена |
| Финансовая система предоставляет только списание, без удержания/освобождения | Сценарий З-7 "удержать при оформлении, списать при приёме" не реализуется буквально | Добавить резерв в авторитетный Онлайн Баланс с согласованным учётом либо изменить бизнес-процесс по согласованию. Подмена удержания немедленным списанием меняет условие задачи и потому не принимается как равнозначное решение                                      |
| Контейнеры и внешние системы имеют раздельные БД и не дают общей транзакции | Нельзя атомарно удержать деньги, создать внешнее отправление и записать заявку одним commit | Локальные транзакции, outbox, промежуточные состояния, повтор по ключу и компенсация RELEASE при доказанном неприёме. Цена - временная рассогласованность и ручная сверка неизвестных результатов                                                                     |
| Существующий REST API нельзя расширить сохранением outbox и долговременных задач | Нельзя обещать продолжение после 202 и падения процесса | Согласованное расширение схемы/модуля или отдельный долговременный оркестратор с собственным журналом. До надёжной фиксации вход возвращает ошибку; очередь в памяти недостаточна                                                                                     |
| В карточке клиента отсутствует исторический сегмент, а финансовая система использует другой ключ | Нельзя достоверно посчитать уникальных клиентов ММСБ на момент регистрации | Таблица соответствий client_id и договоров, снимок сегмента в событии. Для прошлого без истории - UNKNOWN и предупреждение; текущий сегмент не выдаётся за исторический                                                                                               |

Выбранный подход переиспользует существующие контейнеры, а не требует одновременной замены почтовой и финансовой систем. Альтернатива - новый самостоятельный сервис возвратов - отделяет выпуск и масштабирование, но не устраняет отсутствующие внешние контракты и добавляет эксплуатационные границы. Поэтому для объёма из З-8 выбран модуль и воркер в существующем REST API; отдельный оркестратор нужен только при невозможности расширить этот контейнер.
